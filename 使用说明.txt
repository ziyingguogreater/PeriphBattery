外设电量监视  —— 使用说明
================================

【启动】
  双击 PeriphBattery.exe，几秒后任务栏右下角出现图标，不弹窗口。
  首次运行会在同目录生成 config.json。
  如果图标被折叠进「^」里，把它拖到任务栏上即可常驻。
  程序同一时间只允许运行一个：重复双击（哪怕换了目录）只会弹出
  「启动失败 · 已经有一个实例正在运行，请检查系统托盘或任务管理器」。

【图标含义】
  软件图标（绿底）      电量正常，一切正常
  红色感叹号 + 闪烁     有设备低于提醒阈值（同时弹 Windows 通知）
  软件图标（变暗）      勾选的设备都没检测到（未连接 / 接收器拔出）
  黄色感叹号            既没有可用的设备配置，也没有能读到电量的蓝牙设备
  右下角黄色角标        系统通知权限没开，警告功能无法弹出
  变暗 + 黄色角标       配置文件缺失且通知也没开（两样都不行）

  托盘不再显示电池形图标（容易和系统自带的电池图标混淆），
  具体电量请鼠标悬停查看，或打开设置窗口。

【鼠标悬停看到的提示】
  MCHOSE G3 V2，剩余电量90%
  ATK A87Pro：使用有线连接

  如果系统通知权限没开，设备列表下面会多一条分隔线和警告：
  ──────────────
  警告：通知权限未开启，警告功能无法工作。
  单击此处打开通知设置

  通知权限在启动时、以及之后每 60 秒向系统查询一次（不会弹任何窗口）；
  没有权限时，单击托盘图标会直接打开 Windows 的通知设置页，
  在系统设置里开好后图标与提示会自动恢复，不用重启程序。
  如果设备太多导致提示太长，会优先保证这条警告完整显示。

【设置窗口】
  右键图标 → 「设置…」。在里面可以：
    · 勾选 / 取消勾选要监视的设备（取消即停止监视，不再读取也不提醒）
    · 改低电量阈值：下拉里有 10%~50% 的预设值，
      选「自定义…」可填 1~99 的任意整数（留空或填 0 清除自定义项，
      并把阈值重置为默认值 20%）；输入不合法会弹「错误」窗口并清空重填
      改完阈值会立刻按新值重新判断一次，已有设备低于阈值就马上提醒
  · 改检查间隔、重复提醒间隔（手输范围 5~240 分钟，非法输入会被拒绝并还原）
    · 开关「开机自动启动」「设备接入时弹静音提示」
    · 「配置文件…」查看已加载的设备配置（见文末说明）
    · 重新扫描设备（设备插拔后点一下刷新列表）
  点「保存」生效，点「取消」放弃修改。

  设备面板每行显示：勾选框 + 设备名 + 当前状态（如「92%」「USB 供电」「未连接」），
  右上角显示「已启用 2 / 3」这样的计数。
  勾选框：绿色 ☑ 表示正在监视，灰色 ☐ 表示不监视（点一下切换）。
  列表每 1.5 秒自动刷新，插拔设备、换连接方式都会立刻反映，
  已经不存在的设备会自动从列表里消失。
  设备名太长会截断成「MCHOSE G3 V2 Ultra Pro Max S…」，
  鼠标悬停可以看到完整名称、VID:PID、类型和状态。
  设备多于 5 台时面板内出现滚动条，也可以用滚轮滚动；
  装得下时滚动条自动收起。
  点设备名或状态文字也能切换勾选，不用非得点那个小方框。

【手动刷新】
  双击托盘图标，或右键菜单「立即刷新电量」。
  刷新时鼠标悬停会显示「正在刷新…」。

  （单击托盘图标：都正常时打开设置窗口；
   配置文件缺失时先打开配置文件列表；配置文件没问题但通知没开时打开通知设置。）

【启动提示】
  手动双击启动：弹一条静音通知「外设电量监视已启动」，下面是已连接设备，
  按电量从低到高排列（电量最低的在最上面），有线设备排在最后。
  最多列 4 行，超过时最后一行显示「等 N 个设备」。
  例：
      MCHOSE G3 V2 · 47%
      ATK A87Pro · 92%
      MKB87 · USB 供电

  如果启动时已经有设备低于阈值，不再显示上面那条，
  而是直接弹「电量偏低，请及时充电」的警告（带警报音），
  只列出低电量的那几台。

  开机自启（自动启动）：完全静默，只有存在低于阈值的设备时才弹警告。

  如果系统通知权限没开，启动提示不会发送（发了也会被系统吞掉），
  只在日志里记一笔，托盘图标会带黄色角标提醒。

【设备接入提示】
  运行期间插上设备（或从休眠唤醒）会弹一条静音通知：
      MCHOSE G3 V2 已连接
      无线连接 · 剩余电量 90%      （2.4G 接收器）
      蓝牙连接 · 剩余电量 90%      （蓝牙连接时这样说）
  不发声，只是提醒。程序启动时已连着的设备不弹，
  同一设备 10 分钟内也只提示一次，避免休眠唤醒反复打扰。

【通知外观】
  通知横幅左上角的图标固定是软件图标（绿色 USB 图）。
  横幅正文左侧的圆形图标随通知类型变化：
    绿色对勾      启动提示、设备接入提示（静音，不发声）
    红色感叹号    低电量警告、测试通知（带警报音）
  左上角图标由 Windows 外壳缓存，若更换后没有立刻生效，
  重启「Windows 资源管理器」或注销重新登录即可刷新。

【断开 / 重连】
  拔掉设备后图标会变灰并显示断开状态；程序每 10 秒自动重试，
  插回去会自动恢复，不需要重启。
  2.4G / 有线设备关机（接收器或线还插着）也一样判为未连接：
  接收器收不到设备、或只回 0/0 时，不再把上一次的电量当成现在的结果。
  偶发一次读取异常不会立刻判为断开（要连续两次失败），避免状态来回跳。

【右键菜单一览】
  设置…               打开设置窗口
  立即刷新电量        马上读一次（没有在监视的设备时置灰不可点）
  临时停用低电量通知  勾选后不再弹低电量通知，但托盘图标照旧闪烁；
                      只在本次运行有效，重启程序自动恢复
  低电量提醒阈值      10% ~ 50% 快捷切换；设置界面存过自定义值后，
                      这里会多出一项「NN%（自定义）」
  运行自检            先立刻复查一遍通知权限，再检查设备能否读到，
                      发一条测试通知，并让托盘图标闪一下
                      （闪完自动恢复常态图标，不会停在警告图标上）
  查看日志            打开 app.log
  退出

【配置文件 config.json】
  interval_sec        检查间隔（秒）
  low_threshold       低电量阈值（%）
  custom_threshold    自定义阈值（0 表示没有；与预设重复时也会归 0）
  alert_repeat_min    同一设备重复提醒的最小间隔（分钟）
  start_with_windows  开机自启
  notify_on_connect   设备接入时弹静音提示
  device_settings     每台设备的设置，格式：
      "3837:4245": { "enabled": true, "mode": "auto" }
      enabled=false 表示不监视该设备
      mode 可以是 auto / wired / wireless（强制指定连接方式）

  一般用设置窗口改就行，改文件的话记得从托盘菜单退出再启动。

【日志】
  %APPDATA%\PeriphBatteryTray\app.log
  自动轮转：单文件到 512KB 就切分，只保留最近 3 个文件（约 1.5MB 上限）。

【已知说明】
  ATK A87Pro 在 USB 有线供电时，电量字段固定返回 0，
  程序据此判定为「有线连接」并显示 USB 标志，这是预期行为。
  拔掉数据线走 2.4G 时会正常显示电量。

【设备配置文件 device 文件夹】
  首次运行时程序会自动创建 device 文件夹和 config.json（不需要手动准备）。
  程序的电量读取方式全部放在 exe 旁边的 device 文件夹里，
  每个 .json 对应一种设备。以后换设备只要加一个文件，不用重新编译。

  示例（迈从鼠标 mchose-g3.json）：
  {
    "name": "MCHOSE G3 V2",
    "kind": "mouse",
    "match": { "vid": "3837", "usage_page": "FF01", "usage": "10" },
    "request": { "payload": "55 30 A5 0B 2E 01 01 01", "length": 64 },
    "response": { "expect": "AA 30", "level_index": 8, "charge_index": 9 }
  }

  字段说明：
    name               显示名称（软件一律以它为准，内部名称优先）
    kind               mouse / keyboard / generic，决定列表里显示的类型
    match.vid          厂商 ID，十六进制
    match.pid          可选，限定产品 ID，可写成数组；不写表示同厂商都匹配
    match.usage_page   HID 用法页，十六进制
    match.usage        HID 用途，十六进制
    request.payload    要发送的指令（十六进制，空格可省）
    request.length     发送报文总长度（不含开头的 report id 字节）
    response.expect    回包前缀，用来确认这是电量回复；留空表示收到回包就算
    response.level_index   电量在回包里的下标（从 0 开始）
    response.charge_index  充电标志的下标
    response.charge_on     哪些取值算「正在充电 / 有线供电」，默认 [1]
    response.wired_if      例如 {"level":0,"charge":0}：出现这种回包就判定为纯 USB 供电
    response.alive_if      可选，例如 {"index":3,"value":"0B"}：只有第 3 字节
                           等于 0x0B 才算设备在线。2.4G 接收器在设备关机后
                           会把缓存的上一次回包重播出来（数值看着正常、延迟极短），
                           靠这个链路标志位才能识别出「设备已关机」
    response.wired_pids    可选，只有这些 PID 出现上面的回包才算供电。
                           2.4G 接收器的 PID 与有线不同，加上它可以避免
                           无线刚连上时把 0/0 误判成「使用有线连接」
    response.timeout       等回包的超时秒数，默认 1.2

  校验很严格：字段缺失、十六进制写错、索引越界、kind 不认识的配置会被直接忽略，
  既不加载也不出现在列表里（原因记录在 app.log）。
  同名配置只保留最早创建的那份，复制出来的副本会被忽略。

  设置窗口 →「配置文件…」：
    · 显示「已加载 X 个配置文件」和每个文件对应的设备
    · 「添加配置文件…」选一个 json 加进来：先校验，不合法会弹
      「错误 · 无效的配置文件」（系统错误图标 + 提示音），
      合法才复制到 device 文件夹并立即刷新列表；重名或同名文件也会被拒绝
    · 「打开 device 文件夹」直接打开配置文件目录
    · 「刷新」重新读取目录并重建设备列表；发现新设备会弹一条
      「添加设备」通知（通知权限不可用时不弹），并自动纳入监视

【蓝牙设备】
  蓝牙连接的鼠标 / 键盘不需要配置文件：只要 Windows 能给出电量
  （「设置 → 蓝牙和其他设备」里能看到百分比），程序就会自动把它
  加进监视列表，名称就用设备自己的名字，同样参与低电量提醒。
  同一台设备同时连着 USB / 2.4G 接收器时只会显示一条（优先用接口那条）。
  同型号的两台设备（VID/PID 相同）也能同时监视，第二台在后台记为 编号#2；
  蓝牙设备按地址区分，名字一样也不会互相顶掉。

【两种异常状态怎么修】
  1) 托盘是黄色感叹号 → 没有可用的设备配置：
     把设备配置 json 放进 device 文件夹，单击托盘图标打开配置文件列表，
     点「刷新」即可；什么也不做的话，程序每 60 秒也会自动重试一次。
  2) 托盘右下角有黄色角标 → 系统通知权限没开：
     单击托盘图标直达 Windows 通知设置，把本程序的通知开关打开。

  两样都缺时图标是「变暗 + 黄色角标」，单击会先去解决配置问题，
  配置补齐后再单击才跳到通知设置——按最影响功能的那一项优先。
