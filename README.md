> 作者只负责提出需求、实际测试和验收。包括协议逆向、Win32/蓝牙读取、界面与打包脚本，
> 都是 AI 在对话中逐轮生成并修正的结果。
>
> 因此：代码可能带有 AI 生成的痕迹（注释风格、异常兜底策略、命名习惯），
> 也可能存在尚未被发现的问题。**使用前请自行审阅代码**，尤其是 HID 报文解析、
> 注册表写入（开机自启）与通知发送这几部分。欢迎提 Issue 指正。

Windows 托盘小工具：常驻后台读取鼠标 / 键盘的剩余电量，托盘图标用数字直接显示，
低电量自动提醒。支持 USB 有线、2.4G 接收器和蓝牙三种连接方式。

## 功能

- **托盘显示电量**：图标上直接画百分比，鼠标悬停看完整列表（名称、VID:PID、类型、状态）
- **多设备同时监视**：同型号插两台也能分开显示与设置
- **三种连接方式**
  - USB 有线：从设备厂商 HID 接口读电，纯供电时显示「USB 供电」
  - 2.4G 接收器：可识别接收器在、设备已关机的情况（靠回包里的链路标志位）
  - 蓝牙：直接从系统设备属性取电量，**不需要配置文件**，设备断开会自动移出列表
- **低电量提醒**：阈值可设（预设 10%~50% + 自定义 1~99），低于阈值发系统通知 + 图标闪烁
- **临时停用通知**：右键菜单一键静音，图标照旧闪烁，重启自动恢复
- **配置文件化管理**：`device/*.json` 描述「发什么、怎么解析」，可自己添加新设备
- **单实例运行**、DPI 适配、深色界面、通知权限检测

## 使用

### 直接使用（推荐）

到 [Releases](../../releases) 下载 `PeriphBattery-便携版.zip`，解压后双击 `PeriphBattery.exe`。
没有依赖、不用安装，放在任意目录都行。

> 首次启动如果收不到通知，点托盘图标按提示打开「通知和操作」里的开关。

### 从源码运行

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

### 打包

```bash
pip install pyinstaller
pyinstaller --noconfirm PeriphBattery.spec
```

或者直接双击 `build.bat`，产物在 `dist\PeriphBattery.exe`。

## 设备配置

`device/` 目录下每个 json 描述一种设备：

```json
{
  "name": "MCHOSE G3 V2",
  "kind": "mouse",
  "match": { "vid": "3837", "usage_page": "FF01", "usage": "10" },
  "request": { "payload": "55 30 A5 0B 2E 01 01 01", "length": 64 },
  "response": {
    "expect": "AA 30",
    "level_index": 8,
    "charge_index": 9,
    "alive_if": { "index": 3, "value": "0B" }
  }
}
```

- `match`：按 VID / PID / 用法页 / 用途匹配 HID 接口
- `request.payload`：发的原始报文（十六进制）
- `level_index` / `charge_index`：回包里电量与充电状态的位置
- 可选：`wired_if`（哪种回包代表纯供电）、`wired_pids`（只有这些 PID 才算纯供电）、
  `alive_if`（哪个字节等于什么值才算设备在线，用于识别「接收器在、设备关机」）

**不想自己抓协议？** 仓库里带了一份写给 AI 的提示词
[AI提示词-生成设备配置.md](AI提示词-生成设备配置.md)（便携包里也有）。
把它整体发给能在这台电脑上执行命令的 AI，它会用**选择题**带你确认连接方式、让你拔插设备，
逐字节测出回包结构，最后把 json 写好放进 `device/` —— 你不用懂协议，也不用抓包。

字段细节、界面操作、常见问题见 [使用说明.txt](使用说明.txt)。

## 反馈

某台设备读不到电量、或读到的数值明显不对时：

1. 把 [AI提示词-生成设备配置.md](AI提示词-生成设备配置.md) 交给能跑命令的 AI，
   让它带你测一遍。测不出来时它会先判断**是设备本身没这个功能，还是只是没测出来**：
   前者直接用人话解释原因，后者才生成 `反馈-<设备名>.md`
2. 到 [Issues](https://github.com/ziyingguogreater/PeriphBattery/issues/new) 新建一条，
   把报告整段贴进去，附上 `%APPDATA%\PeriphBatteryTray\app.log`

报告里最关键的是：VID/PID、usage_page/usage、试过的请求与回包十六进制、卡在哪一步。
有这些基本能定位问题；只说「不能用」很难查。

## 已知限制

- 只支持 Windows（用到 Win32 / WMI / 系统通知）
- **便携设计**：`config.json` 与 `device/` 都在程序所在目录，程序需要对目录有写权限。
  放到 `C:\Program Files` 这类受保护目录会导致配置存不下来，请放在用户目录或桌面
- 蓝牙设备读的是系统上报的电量，个别设备在系统里本来就不显示电量，程序也读不到
- 2.4G 接收器在设备关机后会重播缓存回包，需要配置里写对 `alive_if` 才能识别（本仓库自带的两个配置已处理）
- **同型号多设备的编号可能漂移**：两台完全相同型号（VID/PID 一致）同时插入时，第二台在后台
  记为 `xxxx:yyyy#2`，序号取决于枚举顺序。拔插后顺序变了，`device_settings` 里保存的
  启用状态/连接方式可能落到另一台物理设备上。
  这是已知的稳定性限制，单设备使用不受影响；不影响电量读取本身，只影响「哪条设置属于哪台」。
  将来改为稳定标识（序列号 / 设备路径哈希 / 接口指纹）时，必须一并做两件事：
  ① **旧配置迁移**（把 `vid:pid`、`vid:pid#2` 平滑映射到新键，不能丢用户已有设置）；
  ② **双设备插拔顺序测试**（两台同型号交替拔插、换 USB 口、重启后再验证设置归属）。
